API keys (.env)

KeyWhat
OPENCODE_API_KEY or OPENROUTER_API_KEYRequired — at least one. This is where any spend goes.
JARVIS_MODELOptional override (default: gemma-4-31b-it:free).
JARVIS_FALLBACK_MODELSComma list, tried right after the default.
GROQ_API_KEY / GROQ_MODELSFree fast fallback (recommended second key).
GEMINI_API_KEY / GEMINI_MODELSOptional third fallback.
OLLAMA_BASE_URL / OLLAMA_MODELS / OLLAMA_FIRSTSelf-hosted. Private, unlimited after hardware.

Running the bot

npm i -g pm2
pm2 start ecosystem.config.js   # or: pm2 start bot.js --name ussr-eco
pm2 save && pm2 startup
pm2 logs ussr-eco --lines 30    # watch boot + Jarvis errors
pm2 restart ussr-eco            # after copying new bot.js / economy_core.js

Always deploy bot.js + economy_core.js together — the bot refuses to boot on a mismatched pair. Never overwrite the server's .env.

Per-server toggles

-setup jarvis                 # status line
-setup jarvis community on    # everyone-talks mode
-setup jarvis bugs off        # silence triage here
-setup jarvis off             # auto-replies off entirely

"Came back empty" — what it means

MessageCause / fix
no AI key in the server .envNo provider key set. Add one, restart.
API key rejected (401)Key wrong or revoked. Replace it.
out of credits (402)Provider balance dry. Top up or wait.
model gone (… 404)Slug retired. Update the chain / set JARVIS_MODEL.
rate-limited (429)Free quota spent. Wait, top up, or add Groq.
network/timeoutDroplet can't reach the provider. Check network/DNS.

Full detail lands in logs as [jarvis-auto] with provider, model, code.

Silence checklist

Nothing answers at all? Check in order: 1) files deployed + restarted, 2) pm2 logs for boot errors, 3) -botstatus (bot alive?), 4) -jarvislimit (pool dry?), 5) -setup jarvis (asleep? muted channel? community off + you're not staff?). A ⏳ reaction means cooldown — wait 30s.
